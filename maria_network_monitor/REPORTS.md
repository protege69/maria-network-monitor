# История и суточные отчёты — 1.4.0

## Обновление существующей установки

1. Сделайте резервную копию приложения и конфигурации HA. Замените файлы приложения в существующем репозитории файлами релиза; не загружайте ZIP как единственный файл репозитория. `maria_network_monitor/config.yaml` должен содержать `version: "1.4.0"`.
2. Обновите сведения репозитория в магазине приложений HA и установите обновление Maria. Не удаляйте приложение: `/data` содержит cache, inventory и теперь журнал отчётов.
3. В настройках приложения проверьте `report_timezone`: пустая строка использует переменную окружения `TZ`, иначе UTC. Можно явно задать `Europe/Moscow`. Выберите часовой пояс до начала сбора. Он показывается в отчёте. Смена пояса при существующем журнале отключает отчёты до миграции, сохраняя мониторинг и старый файл.
4. Существующий YAML dashboard остаётся подключённым. Приложение обновляет только свои сгенерированные файлы. В ресурсах HA измените **существующий** URL модуля на `/local/maria_network_monitor/maria-network-card.js?v=1.4.0`, не создавая дубликат. Обновите dashboard через его меню и перезагрузите страницу браузера.
5. Появится общая view **Отчёт за день**, а на странице каждого филиала — отчёт и **История**. Новые устройства подхватываются автоматически. Дополнительные YAML sensors, utility meters и автоматизации вручную создавать не нужно.

## Что означает число страниц

- Общий счётчик принтера остаётся прежним sensor с прежним `unique_id` и `total_increasing`. Его накопленную историю мы не удаляем.
- «Подтверждено страниц за день» складывает неотрицательные разницы последовательных показаний одного источника, если оба показания относятся к выбранному календарному дню. Повторные значения из кэша с тем же временем не являются новым опросом.
- Первый день наблюдения неполный. Ноль после первой исходной точки означает отсутствие измеренного прироста, а не доказательство отсутствия печати до неё.
- Разница через полночь не распределяется предположительно: в отчёте указаны отдельное количество и границы интервала. Обычный опрос вблизи полуночи также может оставить небольшой нераспределённый прирост.
- Снижение счётчика и смена его источника создают отметку качества и новую исходную точку. Они не считаются отрицательной печатью или огромным приростом. Сброс, полностью скрытый между двумя опросами, невозможно достоверно обнаружить.
- Нет показаний — **нет данных**, не ноль. Для завершённых дней без показания на конец дня есть отдельная отметка. Текущий день всегда предварительный.
- Суммы являются подтверждённой частью расхода по доступным измерениям, а не гарантированным бухгалтерским итогом. Для точной атрибуции печати по времени нужен журнал заданий принтера/print server.
- Счётчик может измерять impressions/pages/sheets в зависимости от модели. Источник не превращает двусторонние отпечатки в количество листов автоматически.

## Хранение и история

Журнал `/data/daily_reports.json` сохраняется атомарно и переживает перезапуск. Удерживаются последние 90 календарных дней; CSV можно скачать для выбранной даты. CSV формируется в браузере, данные не отправляются внешнему сервису. Старые дни до установки этой функции автоматически не импортируются из Recorder.

Снимок inventory и отчёт публикуются retained через MQTT без привязки к доступности процесса: уже полученные данные остаются видимыми при остановке Maria. Свежесть проверяется отдельно. Для нового браузера во время недоступности самого HA данных показать невозможно; сохранённые записи доступны после восстановления HA/брокера. При потере retained database брокера они восстанавливаются из приложения после его подключения.

График «История» использует штатную history-graph карточку HA. Срок подробной истории зависит от Recorder; наличие этой карточки само по себе не меняет его настройки. Не исключайте счётчики страниц и binary sensors связи из Recorder. Большие диагностические Inventory и Daily print report entities можно исключить по их **фактическим** entity_id, оставив числовые и бинарные entities. Сам журнал отчётов от этого не пострадает.

Официальные источники: [History](https://www.home-assistant.io/integrations/history/), [Recorder](https://www.home-assistant.io/integrations/recorder/), [History graph](https://www.home-assistant.io/dashboards/history-graph/), [Card helpers](https://developers.home-assistant.io/blog/2020/02/18/106-custom-card-changes/).

## Плохая связь

API failure сохраняет inventory и сбрасывает серию подтверждений отсутствия. Удаление устройства требует трёх последовательных успешных опросов без lease. Пока отсутствие подтверждается, карточка сохранена и помечена как неактуальная. Ошибка автоматического выбора LAN всё ещё требует исправления `sites[].lan`: смотрите количество static до фильтра и причины исключения в диагностике. Три стабильно ошибочных фильтра не доказывают физическое отсутствие устройства.

Ожидание RouterOS ограничено 20 секундами за цикл; один зависший опрос не создаёт новые параллельные копии самого себя. Повторные ошибки включают задержку до пяти минут. Исторические значения принтера сохраняются независимо от его текущей связи.

Проверьте после установки: версия приложения, отсутствие дубликатов dashboard, прежние MQTT entities, дата/часовой пояс отчёта, две последовательные свежие точки счётчика, график связи, восстановление после одного пропущенного опроса. Полную потерю питания или памяти хоста эти механизмы не исправляют.
